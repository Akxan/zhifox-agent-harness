# 数据存在哪里

下面的路径说的是 clone 下来的情况：项目里的 `data/` 和 `.env`。一行命令装上的，`data/` 换成[一行命令装上](installation.md#一行命令装上更多说明)里你这个账号的那个文件夹
（`~/Library/Application Support/ZhiFox/`、`~/.local/share/zhifox/`、`%LOCALAPPDATA%\ZhiFox\`），`.env` 在它里面；别的都一样。

**只有你自己的账号能读。** macOS 和 Linux 上，`data/` 和里面的文件夹建出来就是 700，文件是 600。Windows 没有这种权限位
（`chmod` 在那里只能改"只读"这一个标记），而你在用户文件夹以外建的文件夹（`C:\code\…`）默认会继承"这台电脑上的所有账号都能读"。
所以 Windows 上智狐对每个文件夹运行一次 `icacls`（[winacl.py](../../harness/winacl.py)）：把 `data\` 和里面的文件夹从上一层继承来的权限去掉，
只给你自己的账号（按 SID 认）、SYSTEM 和管理员完全控制，里面以后新建的文件都继承这一份；保存密钥时 `.env` 也是这三项。
留着 SYSTEM 和管理员，是因为它们本来就什么都读得到（和别的系统上的 root 一样），去掉它们只会让备份和杀毒软件出错。
`icacls` 失败的时候（FAT32 的 U 盘、网络盘），智狐照常运行，在日志里写一句警告。

**保存文件时别的程序正开着它。** 智狐存每个文件都是先写一个临时文件，再一步换上去（中途断电也不会留下半个文件）。
Windows 上，旧文件正被别的程序开着（杀毒软件、索引服务刚好在看它）时，这一步会被拒绝。这种情况一般转眼就过去，
所以智狐隔一小会儿再试，最多试 8 次、一共一秒出头（`config.py` 的 `WINDOWS_REPLACE_TRIES`）；还不行才报错。
macOS 和 Linux 上替换不在乎文件开没开着，不重试。

| 路径 | 内容 |
|---|---|
| `.env` | 各家的 API 密钥。通过网页界面保存时，会把它设成只有你的账号能读（Windows 上靠访问控制列表，见上面） |
| `data/conversations/` | 每一段会话（网页界面、终端界面、定时任务、聊天通道里的都在这儿），一段一个 JSON 文件 |
| `data/media/` | 发过的每个附件的原件，文件名是内容的 SHA-256，同一个文件发十次只存一份。删除会话时（以及每次启动时），没有会话再用的原件会被删掉 |
| `data/memories/` | 助手的长期记忆和笔记。可以在网页的信息栏里查看、修改和删除，也可以手动编辑 |
| `data/skills/` | 装好的 Skill，一个一个文件夹。可以在"扩展 → Skill"里管理，也可以手动改 |
| `data/skills.json` | 哪些 Skill 停用了、每一个是从哪儿装来的 |
| `data/agents/` | 你定制的 Agent，一个一个 Markdown 文件（Claude Code 的 subagent 格式）。可以在"扩展 → Agent"里管理，也可以手动改 |
| `data/todos.json` | 待办事项 |
| `data/tasks.json` | 定时任务，每个任务最近 20 次运行的记录，以及还没关掉的提醒。读不出来时原文件改名为 `tasks.broken.json` 留着，从空的任务列表开始 |
| `data/settings.json` | 你选的模型、同步到的模型列表、自己填的价格、界面语言、每月预算，浏览器和操作整台电脑的设置（`"computer": {"enabled", "unattended", "blocked"}`），命令的沙箱（`"sandbox": {"level", "paths"}`），备用模型（`"fallbacks": {提供方: [模型]}`），关掉了"遮住工具结果里的密钥"的话还有 `"redact_secrets": false`，语音转文字（`"voice": {"provider", "model", "url", "local_model", "endpoint"}`，改过了才写），以及打开了[检查新版本](installation.md#更新)的话的 `"update_check": true`。不含密钥 |
| `data/ledger.jsonl` | 花费账本：每调用一次模型一行（日期、哪一家、哪个模型、对话还是定时任务还是子 Agent、token 数、估算的金额），每转一条语音也一行（来源 `voice`，没有 token，`seconds` 是语音的长短）。超过 90 天的明细合并成每天、每个模型、每种来源一行 |
| `data/mcp.json` | 你接入的 MCP 服务器，格式和 Claude Desktop 的一样，另外有几项智狐自己的（`enabled`、`approval`、`timeout`）。里面可能有服务器的密钥，所以只有你的账号能读，助手的文件工具也打不开它 |
| `data/hooks.json` | 你的[钩子](sandbox-and-hooks.md#你的钩子在固定的时刻运行你自己的脚本)：名字 → 事件、matcher、程序和参数、时限、`onFailure`、`runsIn`、`enabled`。参数里可能有令牌，所以只有你的账号能读，助手的文件工具打不开它，导出时遮住 |
| `data/endpoints.json` | 自定义模型接口：名字、地址、可选的密钥，以及每个模型能做什么、上下文上限和价格。只有你的账号能读；助手的文件工具打不开它；导出时密钥遮住，页面上只看得到最后 4 位 |
| `data/channels.json` | 聊天通道，每个平台一份：凭据（机器人的 token，或者应用的 ID 和密钥；密钥就是钥匙）、机器人的名字、配对的主人的账号编号和名字、确认方式、沙箱的档位、正在用的配对码、每个聊天接着的是哪一段会话，以及 Telegram 的消息读到了哪里。只有你的账号能读；助手的文件工具打不开它；导出时遮住 |
| `data/browser/profile/` | 智狐自己那个 Chrome 的配置文件夹：你在里面登录过的网站的 cookie 和登录状态、缓存、历史记录。只有你的账号能读。"设置 → 浏览器 → 清除"会删掉它 |
| `data/browser/shots/` | 浏览器每一步截图的大图，文件名是内容的 SHA-256。30 天后删掉，对话里的小图还在 |
| `data/desktop/shots/` | 操作电脑每一步截图的大图（你的整个屏幕），文件名是内容的 SHA-256。7 天后删掉，对话里的小图还在 |
| `data/backups/` | 助手整个覆盖某个文件之前，旧版本的备份 |
| `data/backups/turns/` | 文件工具改过文件的每一轮一个文件夹：一份清单，每个文件这一轮之前（和之后）的样子，撤回时为重做留的那一份。只有你的账号能读，30 天后删掉 |
| `data/input_history` | 你在终端版里输入过的话（按上方向键可以找回） |
| `data/updates.json` | 上一次[检查新版本](installation.md#更新)查到了什么：什么时候问的、最新的正式版本（版本号、tag、日期、有没有 wheel）、上一次没查成的原因。只有公开的信息。它只是缓存：导出时不带，恢复时不写，删掉也没关系 |
| `data/restore-backups/` | 每次从备份恢复之前自动留的备份（`zhifox-before-restore-日期-时间.zip`，密钥遮住，最多留最新的 5 份）。从不导出（见"备份和恢复"） |
| `data/logs/` | macOS 上后台服务的日志 `service.log`，以及最多三份旧的（见[在后台一直运行](background-and-servers.md#在后台一直运行)） |
| `data/.web-address`、`data/.web-token` | 后台服务的网页口令（重启前后不变，卸载服务时删掉），和带着它的网页地址。`harness serve --web` 没有终端可以打印的时候（后台服务）写在这里。只有你的账号能读，退出时删掉，导出时不带 |
| `data/.lock` | 正在用这个数据目录的那个智狐占着它，里面记着是哪一种（网页界面、`serve`、后台服务）和进程编号，再开一个的时候好说清楚是谁挡着。导出时不带 |

这些都是可以直接打开的普通文件。`data/` 和 `.env` 都写进了 `.gitignore`，不会被提交到 git。
`data/` 里的文件夹和会话文件都设成只有你的账号能读写，同一台电脑上的其他账号看不到。
网页界面保存密钥之后只显示最后 4 位，不会把完整的密钥发回浏览器。

对话内容会发送给你所选厂商的 API 处理，同时保存在你自己电脑上的 `data/conversations/` 里，
不会上传到别处。接了 MCP 服务器的话，你允许的每一次 MCP 工具调用，参数会发给那个服务器。
打开了浏览器的话，助手打开的网页由智狐自己的 Chrome 从那些网站上取来，那些网站看到的是一次普通的访问；它在上面读到的内容，
和别的工具结果一样发给模型的厂商。
打开了操作整台电脑的话，截下的每一张图（你允许的、这段对话里不再问的、"全部自动允许"下截的）都是你整个屏幕的图，它们也会发给模型的厂商。
在会话栏里删除一段会话，对应的文件也会被删掉。
智狐唯一一个不是你叫它做、自己发出去的请求是[检查新版本](installation.md#更新)，而且默认关着：打开以后每天问一次 GitHub 最新的发布版，
GitHub 看得到的只有你的 IP 地址。

想直接看某段会话的文件，点会话栏里它那一行上的"在访达中显示"。这些"在访达中显示"按钮（会话、记忆、定时任务、待办、
提示词、MCP 服务器、Skill、多媒体里每一项上的，以及记忆、Skill 和浏览器配置文件夹的按钮），除了下面说的一个例外，是页面上仅有的会让电脑启动别的程序
（文件管理器）的按钮，所以服务器对它们格外小心：页面只能告诉服务器"哪一段会话""哪一条记忆"（列表里给它的名字，
按下面说的办法检查）、"哪一个 Skill"（只能是一段名字，而且必须是 `data/skills/` 里真实存在的一个文件夹）、
"哪一个附件"（"会话/第几条消息/第几个"这样的编号，在索引里查过；文件名由内容的 SHA-256 定）、
助手自己的哪一个数据文件（`tasks`、`todos` 或 `prompt`），或者打开记忆、Skill 的文件夹、`data/mcp.json`、`data/hooks.json` 和浏览器的配置文件夹时什么都不用说；
路径由服务器自己算，页面没有办法让它打开别的路径。下载附件也是这样：页面只给编号，文件以下载的方式回来
（`Content-Disposition: attachment`、`X-Content-Type-Options: nosniff`），写着 HTML 的文本文件也只当成文字。
浏览器截图的大图也是这样取的：页面只给它的编号（64 个十六进制字符，拼不出任何路径），回答一律是 `image/jpeg`，
带着同样的响应头，再加上 `Content-Security-Policy: default-src 'none'; sandbox`；操作电脑的截图大图从 `/api/computer/shot` 取，规矩一模一样。
除此以外，服务器只会把应用图标（`/icons/<名字>`）的字节发给浏览器：智狐自带的六张 PNG，按名字在一张固定的名单里查（从不拼路径），
一律是 `image/png`，带着 `nosniff` 和 `Content-Security-Policy: default-src 'none'; sandbox`；里面没有一样是你的数据。
Linux 上没有通用的"选中某个文件"的办法，打开的是文件所在的文件夹。
还有一个按钮会启动别的程序：macOS 上"操作整台电脑"一栏里的"打开系统设置"，它用 `open` 打开两个固定的 `x-apple.systempreferences:`
地址之一（屏幕录制或者辅助功能）。页面只能说 `screen` 或 `input`，地址由服务器定；它只是打开那一页，从不改任何设置。

保存一个本地的 MCP 服务器，就是让智狐在你的电脑上运行这个命令（现在，以及之后每次启动）。所以守着这几条：
只有带着这次运行的口令的页面能保存；命令用参数列表启动，不经过 shell，参数里有什么字符都不会被当成命令的一部分；
模型没有任何能添加或修改服务器的工具，它的文件工具在任何模式下都碰不了 `data/mcp.json`；
这些程序拿不到各家模型的 API 密钥，配置里想把密钥转交出去（`${ANTHROPIC_API_KEY}`）会被拒绝；
环境变量和请求头的值不会发到浏览器，只有最后 4 位；别的工具的配置文件只在你打开导入页的时候读，只复制你勾选的服务器，
它们"不用问"的设置不复制。
MCP 工具调用的参数会发给那个服务器（它可能在网上），所以在确认卡片上看清楚再允许。

在信息栏里查看、修改、删除一条记忆也是同样的防法：页面送回来的是列表里给它的名字（比如 `projects/zhifox.md`），
服务器从记忆文件夹出发一层一层地走到这个文件，凡是会走出这个文件夹的都不认：`..`、绝对路径、指向别处的符号链接。
它只删普通的文件；删完之后空下来的子文件夹也一起删掉。编辑时给的新名字只能是一段名字（不能带 `/`，不能以 `.` 开头），
所以记忆可以改名，但挪不出它所在的文件夹；新内容先写进临时文件再一步换上去，保存失败也不会留下半个文件。

## 备份和恢复

**设置 → 导出全部数据** 会把数据文件夹打成 `zhifox-backup-日期-时间.zip` 下载下来：会话、记忆、待办、设置、
花费账本，以及以后的功能放在这个文件夹里的东西。里面没有任何 API 密钥：密钥在 `.env` 里，它从不导出，不管它是在数据文件夹旁边
（clone 下来的）还是在里面（一行命令装上的）；数据文件夹里别的像 `.env` 这样的文件也会跳过。`data/mcp.json` 存在的话照样导出，但所有密钥都换成
`<removed-from-backup>`：环境变量、请求头、名字像 key、token、password 的字段、`--token` 这类开关后面的值、网址里的密码，
以及长得像 API 密钥的字符串；名字都留着，恢复以后知道要填回哪几项。这个文件不是合法的 JSON 的话，整个不导出，
宁可少导出一份也不冒险带出密钥。`data/channels.json` 里每个机器人的 token、应用的密钥和正在用的配对码，
导出时也同样换成 `<removed-from-backup>`（应用的 ID 留着）。`data/hooks.json` 也一样处理（钩子的参数里可能有令牌，比如 `--token xxx`），
`data/endpoints.json` 也是。符号链接也不导出，因为它可能指向你电脑上的任何地方。压缩包里有一份
`README-backup.txt`，写着导出的时间、怎么恢复、哪些文件做了处理或者没有导出；另有一份写给程序看的 `backup-manifest.json`
（格式的版本、带时区的导出时间、哪些文件遮了密钥）。压缩包在数据文件夹以外的临时文件里生成，发给浏览器之后就删掉。

**在网页上恢复：设置 → 从备份恢复…**

1. 选那个压缩包（或者直接拖进窗口）。它先传给智狐检查一遍；有问题的压缩包会被拒绝并说明原因，什么都不写。
2. 预览里写着它是什么时候导出的、里面有什么（几段会话、几条记忆、待办、定时任务、Skill、Agent、MCP 服务器……）、
   两种方式各会把每一样怎么样，以及哪些密钥恢复以后要重新填。
3. 选一种方式，确认（覆盖会在原地再问一次）：
   - **覆盖**：数据文件夹变成备份时的样子。每一样都换成备份里的，备份里没有的那几样清空。存着密钥的文件是例外，见下面。
   - **合并**：只往里加。会话按编号、记忆和 Agent 按文件名、Skill 按文件夹、多媒体按内容，现在没有的加进来，已经有的原样留着。
     整份的文件（设置、待办、定时任务、花费账本、MCP、聊天通道、钩子……）现在有就留着现在的，没有才用备份里的：
     两份设置一项一项拼起来，会拼出一份谁都没用过的设置（钩子指着另一台电脑上的脚本、聊天通道配对的是另一个人）。
4. 写之前，智狐先把现在的数据文件夹导出一份，放在 `data/restore-backups/zhifox-before-restore-日期-时间.zip`
   （和导出一样遮住密钥；最多留最新的 5 份，导出时不带这个文件夹）。结果那一页上有"在访达中显示"
   （文件资源管理器、文件管理器）的按钮，还列出哪些密钥还是占位符。

**你的密钥绝不会被占位符盖掉。** `mcp.json`、`channels.json`、`endpoints.json`、`hooks.json` 里，备份中的每一个
`<removed-from-backup>` 都去现在的文件里找"同一处"（同一个 MCP 服务器的同一个环境变量、编号相同的自定义接口、
`--token` 后面的同一个参数、除了密码一模一样的网址）：现在那里有真的值，就留着现在的；没有的照样写进占位符，
预览和结果里写明去哪儿重新填（扩展 → MCP、扩展 → 通道、设置 → 自定义模型接口、扩展 → 钩子）。现在有、备份里却没有对应位置的密钥
（只有这台电脑上才有的服务器）也会列出来：覆盖以后它们就没了。现在的文件读不懂的不动它；备份里没有的存着密钥的文件，
覆盖时也原样留着。

**压缩包是不可信的输入。** 只认导出会写的那些东西，名单和导出共用一份（`export.PARTS`）；别的一律拒绝，什么都不写：
带 `../` 的路径、绝对路径、盘符和 Windows 的路径花招（`a:b`、`CON`、`PROGRA~1`、尾巴上的点，用 `pathnames.archive_trick` 检查）、
符号链接和设备文件、加密的项、只差大小写的两个名字、像 `.env` 的文件、`browser/profile/`、`.web-token`、`.lock`，以及不在名单上的名字。
大小有上限（`config.py` 里的 `RESTORE_MAX_*`：解开以后一共 8 GB、一个文件 2 GB、20 万项；网页上传本身最多 4 GB，上传之前就查），
压缩包里写的大小还要和实际读到的对一遍，所以压缩炸弹到了上限就停。`README-backup.txt` 和 `backup-manifest.json` 只读，不写进数据文件夹。

**什么时候拒绝，恢复以后怎样。** 恢复不排队：你的这一轮对话还没结束、有定时任务正在运行、聊天通道里正在进行一轮的时候，
直接拒绝并说明原因。否则智狐先停下定时任务、聊天通道、MCP 服务器和它的浏览器，再写文件（每一样先在数据文件夹里的一个临时文件夹里摆好，
再换上去；哪一步出了错都换回原样），然后照着恢复的数据在原地重新开起来，和启动时一样：端口、链接、事件流都不变，
页面照着新的状态重画就行（不用刷新、不用重启，界面语言也跟着恢复的设置走）。

**在终端里**（没有网页的服务器上）：先退出智狐，再运行

```bash
uv run harness restore zhifox-backup-….zip            # 覆盖
uv run harness restore zhifox-backup-….zip --merge    # 合并
uv run harness restore zhifox-backup-….zip --yes      # 不问（没有终端时必须带上）
```

```powershell
uv run harness restore .\zhifox-backup-….zip
uv run harness restore .\zhifox-backup-….zip --merge
```

它打印同样的预览，要你输入 `yes`，同样先自动备份，做的时候一直占着数据目录的锁，智狐不会在半路被开起来。
智狐正开着的话，它会说是哪一个在运行，请你用那边网页上的按钮。终端直接读文件，所以没有 4 GB 的上传上限（解开以后的上限照样有）。

**最后一招，手动恢复：** 先退出智狐，把现在的数据文件夹挪到一边（默认是项目里的 `data/`；一行命令装上的，是你这个账号的那个文件夹，
`harness doctor` 会告诉你是哪个），把压缩包解压到一个新建的空 `data/` 里
（`unzip zhifox-backup-….zip -d data`；PowerShell 里是 `Expand-Archive .\zhifox-backup-….zip -DestinationPath data`），
删掉里面的 `README-backup.txt` 和 `backup-manifest.json`，再启动智狐。原来存着密钥的那几个文件现在是占位符，要把密钥重新填上。
千万不要解压到正在用的数据文件夹上：占位符会把你现在的密钥盖掉。
